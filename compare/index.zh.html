    • 文件里装得下什么？

    一个 AI 角色散落在许多文件里——一张卡片、一份 Markdown 灵魂、一个虚拟形象、一个记忆包。一张表，列出每种文件承载什么，又在途中丢掉什么。

    COF · CHARACTER OPEN FILE

    这并非谁的选择。角色扮演应用沿用了角色卡；智能体框架用 Markdown 文件；VTuber 用 VRM；记忆项目各有各的包。每种格式在自己的层面上表现出色，却看不见其他层面，于是一个活在多处的角色，就成了几个渐行渐远的文件。COF 是把它们装在一起的容器——一个带清单的 ZIP，开放，并对年龄、权利和同意设有规则。本页将它与它所兼容的各种格式逐项对比，也包括 COF 不具备的功能。

    七种格式，以其公开发布的版本为准：Character Card V2（chara PNG 及其 JSON，SillyTavern 及同类应用的事实标准）、Character Card V3 / .charx（其 2024 年的后继者，一个带素材的 ZIP）、智能体 Markdown（OpenClaw 和 Hermes 所读取的 SOUL.md、IDENTITY.md、AGENTS.md）、Letta Agent File .af（一个序列化的有状态智能体）、MacPaw Portable Memory .mem（用户自有的记忆包，2026 年）以及 VRM 1.0（基于 glTF 的人形虚拟形象，带有唯一成熟的权限块）。按列阅读：该格式的文件在脱离生成它的应用时，自身能对一个角色说出什么。

    COF 不打算做的事

    装进单张 PNG

    卡片是一张可以随处发布的图片，而且始终是图片。.cof 则是一个压缩包。它可以导出 ccv3 PNG（很快还能导出 .charx），但文件本身需要能打开 ZIP 的工具——而所有工具都能。

    运行智能体

    Letta 的 .af 携带工具、工具规则、模型配置和消息历史。COF 只携带角色，并声明 executableContent: none。由什么来运行它，是宿主的事——这是有意为之。

    定义骨骼绑定

    VRM 定义骨骼和表情。COF 将 VRM 或 GLB 作为文件随附，连同其权利和贴图，并在其周围添加姿势、片段和声音。骨骼绑定仍归 VRM。

    证明删除

    MacPaw 的 .mem 会写入墓碑记录和审计日志，因此可以证明一段被遗忘的记忆已在各处被遗忘。COF 在导出时清除（cof extract），且不留任何痕迹——目前如此。

    目前只有 COF 能做的事

    预设

    一个文件，多个即用组合：同一角色的 29 岁和 65 岁、工作版和全年龄版、法语版和日语版。其他格式每个版本都需要一个文件，各版本会逐渐走样。

    有过去，有内心生活，还有缘由

    带日期的记忆，包含人物、地点、事件和感受；由价值观、信念、欲望和恐惧构成的心理，每一项都关联到它所源自的记忆，并带有强度和时间跨度。智能体格式保存散文；记忆格式保存事件；两者都不保存二者之间的联系。

    由验证器强制执行的规则

    每个预设都声明年龄；涉及未成年人的裸露或亲密内容会使文件无效，而不只是被打上标签。真人需要同意记录。可执行文件、pickle 和不安全路径一律拒绝。无需任何人信赖作者的善意。

    从宿主回写

    角色在 OpenClaw、Hermes 或某次聊天中的经历，会作为新的个人记忆回到同一个文件（cof memory add）——并随用户一同离开。一个角色，两个家，一份记忆。

    兼容，而非取代

    这张表的重点不在于 COF 打了最多的勾，而在于 COF 不要求任何人放弃任何东西：一个 .cof 包含一张有效的 Character Card V3，可导出 ccv3 PNG、卡片 JSON、SOUL.md / IDENTITY.md 以及完整的智能体工作区，并将 VRM 作为普通文件保存。其他各列的格式既是它的输入，也是它的输出。凡是 COF 没有对应物的地方——骨骼绑定、运行时、带签名的删除——正确的做法是随附另一种格式，表中以 → 标示。

    灰色行是带日期的承诺，而非现有功能。它们来自公开的路线图；修改格式的 RFC 在发布前开放征求意见。
