What fits in the file?

An AI character travels in many files — a card, a Markdown soul, an avatar, a memory bundle. One table of what each of them carries, and what it drops on the way.

COF · CHARACTER OPEN FILE

Nobody chose this. Role-play apps settled on the character card; agent frameworks on Markdown files; VTubers on VRM; memory projects on their own bundles. Each format is good at its layer and blind to the others, so a character that lives in several places exists as several files that drift apart. COF is the container that holds them together — a ZIP with a manifest, open, with rules about ages, rights and consent. This page compares it with the formats it embraces, feature by feature, including the ones COF does not have.

Seven formats, as published: Character Card V2 (the chara PNG and its JSON, the de-facto standard of SillyTavern and its kin), Character Card V3 / .charx (its 2024 successor, a ZIP with assets), agent Markdown (SOUL.md, IDENTITY.md, AGENTS.md as OpenClaw and Hermes read them), Letta Agent File .af (a serialized stateful agent), MacPaw Portable Memory .mem (a user-owned memory bundle, 2026) and VRM 1.0 (the humanoid avatar on glTF, with the only mature permission block). Read as columns: what a file in that format can say about a character on its own, without the application that made it.

Hover a mark to read its note. A green mark means the format defines the thing; whether a given application uses it is another matter — most apps read a fraction of any format, COF included.

What COF does not try to do

Fit in a single PNG

A card is a picture you can post anywhere, and it stays a picture. A .cof is an archive. It exports a ccv3 PNG (and soon a .charx), but the file itself needs a tool that opens ZIPs — every tool does.

Run the agent

Letta's .af ships the tools, the tool rules, the model configuration and the message history. COF ships the character and declares executableContent: none. What runs it is the host's business, on purpose.

Define a rig

VRM defines the bones and the expressions. COF carries a VRM or a GLB as a file, with its rights and its textures, and adds the poses, the clips and the voice around it. The rig stays VRM's.

Prove a deletion

MacPaw's .mem writes tombstones and an audit log, so a forgotten memory can be shown to have been forgotten everywhere. COF purges on export (cof extract) and keeps no trace of it — yet.

What only COF does, today

Presets

One file, several ready-to-use combinations: the same character at 29 and at 65, for work and for everyone, in French and in Japanese. Other formats need one file per version, and the versions drift.

A past and an inner life, with a why

Dated memories with who, where, what and how it felt; a psyche of values, beliefs, wants and fears, each tied to the memory it comes from, with a strength and a time span. Agent formats keep prose; memory formats keep events; neither keeps the link between the two.

Rules a validator enforces

Every preset declares an age; nudity or intimate content with a minor makes the file invalid, not merely tagged. A real person needs a consent record. Executables, pickles and unsafe paths are refused. Nobody has to trust the author's good faith.

Write-back from the host

What the character lived in OpenClaw, in Hermes or in a chat comes back into the same file as new, personal memories (cof memory add) — and leaves with the user. One character, two homes, one memory.

Embrace, don't replace

The point of the table is not that COF wins the most ticks. It is that COF does not ask anyone to abandon anything: a .cof contains a valid Character Card V3, exports a ccv3 PNG, a card JSON, SOUL.md / IDENTITY.md and a whole agent workspace, and keeps a VRM as a plain file. The formats in the other columns are its inputs and its outputs. Where COF has no equivalent — a rig, a runtime, a signed deletion — the right move is to carry the other format, and the table says so with a ↗.

The grey rows are promises with a date, not features. They come from the public roadmap; the RFCs that change the format are open for comments before they ship.

Sources

  • Character Card V2 — the chara_card_v2 specification (SillyTavern, Risu, Chub) and its PNG tEXt chara embedding.
  • Character Card V3 / CHARX — kwaroran/character-card-spec-v3, SPEC_V3.md (MIT): assets, creator_notes_multilingual, source[], dates, group_only_greetings, the embeded://assets/ folders.
  • Agent Markdown — OpenClaw's SOUL.md / IDENTITY.md, Hermes Agent profiles, the AGENTS.md convention; what COF writes is documented in the 1.2.2 notes.
  • Letta Agent File — letta-ai/agent-file (Apache-2.0) and the AgentFileSchema of the letta package: agents, groups, blocks, files, sources, tools, mcp_servers, skills; no passages, no format version field.
  • MacPaw Portable Memory — MacPaw/portable-memory (MIT), format 1.1: episodes, resources by reference, tombstones, CHECKSUMS, optional Ed25519 signatures; RFC 0001–0003 towards 1.2.
  • VRM 1.0 — vrm-c/vrm-specification: humanoid bones, 18 expression presets, the meta permission block (avatar permission, violent and sexual usage, commercial use, redistribution, modification, credit).
  • COF — spec 1.2, RFC 0002–0006, roadmap. Corrections welcome through the issues: a wrong mark in this table is a bug.
