    AIキャラクターは多くのファイルに分かれて行き来します。カード、Markdownの「魂」、アバター、記憶バンドル。それぞれが何を運び、途中で何を落とすのかを一枚の表にまとめました。

    COF · CHARACTER OPEN FILE

    誰かが選んだわけではありません。ロールプレイアプリはキャラクターカードに、エージェントフレームワークはMarkdownファイルに、VTuberはVRMに、記憶系プロジェクトはそれぞれ独自のバンドルに落ち着きました。どのフォーマットも自分の層では優れていますが、ほかの層は見えていません。そのため、複数の場所で生きるキャラクターは、少しずつ食い違っていく複数のファイルとして存在することになります。COFはそれらをひとつにまとめるコンテナです。マニフェスト付きのZIPで、オープンであり、年齢・権利・同意に関するルールを備えています。このページでは、COFが取り込むフォーマットと機能ごとに比較します。COFにない機能も含めて。

    公開されている7つのフォーマットを取り上げます。Character Card V2（chara PNGとそのJSON。SillyTavernとその系統の事実上の標準）、Character Card V3 / .charx（2024年の後継で、アセット入りのZIP）、エージェント用Markdown（OpenClawとHermesが読むSOUL.md、IDENTITY.md、AGENTS.md）、Letta Agent File .af（状態を持つエージェントをシリアライズしたもの）、MacPaw Portable Memory .mem（ユーザーが所有する記憶バンドル、2026年）、そしてVRM 1.0（glTFベースの人型アバターで、唯一成熟した許諾ブロックを持つ）。各列は、そのフォーマットのファイルが、作成したアプリケーションなしに単独でキャラクターについて何を語れるかを示します。

    マークにカーソルを合わせると注記が表示されます。緑のマークは、そのフォーマットがその項目を定義していることを意味します。個々のアプリケーションが実際に使うかどうかは別の問題です。COFを含め、ほとんどのアプリはどのフォーマットも一部しか読みません。

    COFがあえてしないこと

    PNG1枚に収めること

    カードはどこにでも投稿できる画像であり、画像のままです。.cofはアーカイブです。ccv3 PNG（まもなく.charxも）を書き出すことはできますが、ファイル自体を開くにはZIPを扱えるツールが必要です。とはいえ、どのツールでも扱えます。

    エージェントを実行すること

    Lettaの.afはツール、ツールのルール、モデル設定、メッセージ履歴を含みます。COFが運ぶのはキャラクターで、executableContent: noneを宣言します。何がそれを動かすかは、意図的にホストに委ねています。

    リグを定義すること

    ボーンと表情を定義するのはVRMです。COFはVRMやGLBを権利情報とテクスチャごとファイルとして同梱し、その周りにポーズ、クリップ、声を加えます。リグはVRMの領分のままです。

    削除を証明すること

    MacPawの.memはtombstoneと監査ログを書き込むため、忘れられた記憶があらゆる場所で忘れられたことを示せます。COFはエクスポート時に除去しますが（cof extract）、その痕跡は残しません。今のところは。

    現時点でCOFだけができること

    プリセット

    1つのファイルに、すぐ使える複数の組み合わせ。29歳と65歳の同じキャラクター、仕事用と全年齢向け、フランス語と日本語。ほかのフォーマットではバージョンごとに1ファイルが必要で、バージョン同士が食い違っていきます。

    過去と内面、そして理由

    誰と、どこで、何が起き、どう感じたかを備えた日付付きの記憶。価値観、信念、欲求、恐れからなるプシュケは、それぞれが由来する記憶に結びつき、強さと期間を持ちます。エージェント系フォーマットは文章を、記憶系フォーマットは出来事を保持しますが、両者のつながりを保持するものはありません。

    バリデーターが強制するルール

    すべてのプリセットは年齢を宣言します。未成年を含む裸体や親密な内容は、タグが付くだけでなくファイルそのものが無効になります。実在の人物には同意の記録が必要です。実行ファイル、pickle、安全でないパスは拒否されます。作者の善意を信じる必要はありません。

    ホストからの書き戻し

    OpenClaw、Hermes、あるいはチャットでキャラクターが体験したことは、新しい個人的な記憶として同じファイルに戻り（cof memory add）、ユーザーとともに持ち出されます。ひとりのキャラクター、ふたつの居場所、ひとつの記憶。

    置き換えず、取り込む

    この表の要点は、COFのチェックが一番多いことではありません。COFは誰にも何も捨てることを求めないという点です。.cofは有効なCharacter Card V3を内包し、ccv3 PNG、カードJSON、SOUL.md / IDENTITY.md、エージェントのワークスペース一式を書き出し、VRMはそのままのファイルとして保持します。ほかの列のフォーマットは、COFの入力であり出力です。リグ、ランタイム、署名付き削除のようにCOFに相当するものがない場合は、ほかのフォーマットを同梱するのが正しいやり方であり、表では→でそれを示しています。

    グレーの行は機能ではなく、日付付きの約束です。公開ロードマップに基づいており、フォーマットを変更するRFCはリリース前にコメントを受け付けています。
