Nouveau personnage complétude —

Identité

Les champs marqués * sont obligatoires (nom, âge et sa base, fictif ou non, morphologie) : ce sont, avec les droits, les seules obligations du format. Tout le reste est optionnel. Un fichier peut contenir plusieurs identités (casting) : chaque preset se rattache à l'une d'elles.

Éléments et déclinaisons

Sept catégories par nature de média. Chaque déclinaison déclare son type ; rien n'est obligatoire ; les presets combinent les déclinaisons à l'étape suivante.

Presets

Un preset = une identité + une combinaison de déclinaisons. Une déclinaison par type, sauf les cumulables (vêtements, accessoires, pilosité, particularités, plusieurs LoRA) — vérifiées par région du corps. Le preset par défaut est chargé à l'ouverture ; sa vue de visage de face devient la vignette.

Un preset peut hériter d'un autre (extends) et ne redéfinir que certaines catégories.

Droits

Défauts restrictifs (modèle VRM). Le consentement est obligatoire dès qu'une personne réelle est impliquée — il se rattache à une identité.

Contrôles

Jamais bloquants : le format rend visible, il n'interdit pas. Seules les erreurs de structure empêchent le build.

Résultats
  • Aucun contrôle lancé.
Cohérence par IA (optionnel) — passerelle API OpenAI-compatible

Le builder envoie le dossier du preset (textes, vignettes, descripteurs) et attend un JSON {score, issues[]} — contrat dans docs/coherence-api.md. Le score est stocké avec le nom du modèle ; il ne bloque rien.

Priorités (quand plusieurs représentations décrivent la même chose)

Défauts par usage cible (jeu 3D : avatar d'abord ; chat texte : descriptif d'abord) appliqués automatiquement ; modifiables dans le manifeste.

Build

Génère le fichier .cof (ZIP : mimetype en première entrée, manifeste en seconde, binaires stockés sans compression, hashes SHA-256).

Options
Le ré-encodage vidéo dans le navigateur arrive dans une prochaine version ; pour l'instant les vidéos sont embarquées telles quelles (plafond 20 Mo, désactivable avec alerte).
